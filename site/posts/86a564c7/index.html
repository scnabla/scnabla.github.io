scnterm 基于 WezTerm 的终端改版与使用指南

发表于2026-11-08|更新于2026-11-08|软件

现代化终端：WezTerm

WezTerm

WezTerm 是由 Wez Furlong 开发、使用 Rust 编写的跨平台终端模拟器，支持 Windows、Linux 和 macOS。它提供标签页、分屏、字体与配色设置，也支持本地和远程终端会话管理。外观、快捷键、启动程序等通过 Lua 配置文件设置，内置 SSH 和串口连接功能。

终端负责显示输出、接收输入；PowerShell、Bash、Zsh 等 Shell 负责解释和执行命令。更换终端软件，可以继续使用原来的 Shell、开发工具和命令行工作流。WezTerm 的已有功能与配置说明见 官方功能列表和配置文档。

ScnTerm：我的个人维护版本

  • scnterm 是我基于 WezTerm 维护的个人终端项目，源码放在 scnabla/scnterm。我希望继续使用它已有的终端能力和 Lua 配置，同时能直接修改日常使用中不顺手的交互。

  • 我目前使用 Ubuntu 和 Windows，也为以后使用其他设备保留了 macOS 的构建与发布。现阶段完成的调整包括关闭确认、应用名称与图标，以及独立的自动构建和下载入口。分屏、SSH、串口等基础能力沿用 WezTerm 的实现。

  • 这个分支以官方提交 e68a8ec27727fbbda15e07f0a0737cd5e16481f6 为开发基准，保留上游历史及 MIT 许可证。后续我会按合并、检查和验证的流程接入上游更新。

目前我在 scnterm 中做的修改

[关闭/确认]弹窗支持方向键

我保留了关闭前的确认界面，在原有 Y、N 和鼠标操作上增加方向键选择与 Enter 确认。关闭窗格、标签页或窗口时，只要当前设置要求确认，就可以使用这套操作。确认项继续显示为 [Y]es 和 [N]o。

操作 行为
打开确认界面 默认选中 [N]o
← 选中 [Y]es
→ 选中 [N]o
Enter 执行当前选项
Y 直接确认关闭
N 或 Esc 取消关闭
鼠标点击选项 执行对应操作

默认选中“否”，因此弹出确认界面后直接按 Enter 会取消关闭。需要关闭时，按左方向键再按 Enter 即可。原有 Y、N、Esc 和鼠标操作继续可用。

关闭确认是否出现，仍由 window_close_confirmation、关闭动作的 confirm 参数以及允许直接关闭的进程名列表控制。修改位于关闭确认实现。

应用名称与独立图标

我给 scnterm 选定了橘黄色圆角背景，左侧用玫红色 >，右侧用紫色光标横线。Windows 程序和安装器、Linux 窗口和安装包、macOS 应用包统一使用这套图案，并分别生成 ICO、PNG 和 ICNS 资源。

名称调整覆盖应用菜单、调试面板、连接提示等原有软件名称位置。我也把下载文件和解压后的外层目录统一改成 scnterm，macOS 应用包使用 scnterm.app。

保留原有命令和配置接口

这次我把软件显示名与命令名分开处理，保留原有命令和配置接口。当前安装包里的程序仍叫 wezterm、wezterm-gui 和 wezterm-mux-server，Lua 仍使用 require 'wezterm'，配置文件仍叫 wezterm.lua。

因此，命令示例中的 wezterm 是实际可执行文件名。已有配置里的模块引用和配置路径可以继续使用，涉及本机字体、Shell 和目录的设置则按目标设备调整。

后续个性化开发计划

Linux 窗口控制按钮

我在 Ubuntu 26.04.1、GNOME、Wayland 环境中遇到了窗口右上角没有最小化、最大化和关闭按钮的问题。后续准备检查窗口装饰的协商和绘制行为，补齐默认配置下的窗口控制入口，并验证拖动、缩放及不同装饰配置。

我已将它记为 SCN-001，排查方向和验收要求保存在待修复问题中。

完善串口开发体验

我希望后续能直接用 scnterm 处理 UART 串口开发，计划按以下顺序完善现有功能：

  1. 开放数据位、校验位、停止位和流控配置，支持明确选择无流控。
  2. 增加可用端口列表、设备选择和常用连接配置。
  3. 完善连接状态、主动断开、设备拔出提示和重新连接。
  4. 增加串口日志保存，再独立评估十六进制（HEX）收发、时间戳和定时发送。

这部分会先围绕我使用的 Ubuntu 和 Windows 连接实际 UART 设备验证，涉及共享代码时同时检查 macOS 兼容性。

沿用和调整 Lua 配置

scnterm 继续使用 WezTerm 的配置查找方式。常用位置包括：

系统 配置位置
Windows %USERPROFILE%\.wezterm.lua 或 %USERPROFILE%\.config\wezterm\wezterm.lua
Linux、macOS ~/.wezterm.lua 或 ~/.config/wezterm/wezterm.lua

Windows 还支持读取程序目录中的 wezterm.lua，该位置优先于普通用户目录配置。需要明确指定配置时，可使用 --config-file。原有配置文件中的 require 'wezterm' 保持原样。

程序内原有更新检测仍查询 WezTerm 官方发布源，因此示例设置 check_for_updates = false。scnterm 的版本更新从自己的 Release 页面下载；自动构建发布负责生成和更新下载文件，不会自动替换电脑上的程序。

我日常使用的字体、背景图、窗格焦点提示、中文命令面板和快捷键保存在 personal-config。这套配置独立维护，安装 scnterm 后不会自动启用。具体设置写在之前的 Windows WezTerm 个人配置中，需要相同外观和操作习惯时可以参考。

SSH 连接

scnterm 保留了内置 SSH 客户端，默认使用 libssh。它读取 SSH 配置、完成服务器指纹检查与认证，再把远程终端的输入输出接入窗格。

这种连接只要求远端提供 SSH 服务。属于同一远程连接的新标签页或窗格可以复用已有认证，在 SSH 会话中创建新的通道。

如果需要断线后重新连接原来的远程会话，可以配置 SSHMUX，由远端的 wezterm-mux-server 管理终端进程。它要求远端安装兼容的命令行和服务程序，并在断开期间保持远端服务运行。

在普通 Shell 里直接输入 ssh，调用的是系统找到的 SSH 程序；使用 wezterm ssh 才会进入这里介绍的内置客户端。实现说明见项目的 SSH 文档。

UART 串口连接

scnterm 继承了串口终端功能，通过 serial2 库访问系统串口。UART 是开发板常用的串行通信接口，经 USB 转串口设备连接电脑后，可使用系统识别出的端口名打开终端。

端口名称和波特率需要按实际设备填写。经常使用的端口也可以放入 Lua 的 serial_ports 配置，并从启动菜单选择。

当前公开配置项主要是端口和波特率。底层默认使用 8 位数据、无校验、1 位停止位，以及 XON/XOFF 软件流控，即通过控制字符通知对端暂停或继续发送。设备要求无流控或其他通信参数时，需要进一步开放底层已有的设置接口。我已把这项工作记入待办，准备在后续串口功能开发中处理。

现有窗口按照终端规则解析收到的数据，适合文本日志和设备命令行。用于二进制协议调试的十六进制（HEX）收发与原始字节查看属于后续独立功能。

scnterm 的自动构建与版本更新

我将 WezTerm 上游的构建步骤整理到 scnterm 自己的 GitHub Actions 流程中。向默认分支 personal 推送提交后，自动编译、测试和打包；所有要求的平台任务通过后，才更新 latest Release。

平台 架构 当前流程
Windows x86_64 编译、测试、打包与发布
Ubuntu 26.04 x86_64 编译、测试、打包与发布
Ubuntu 22.04 x86_64 编译与测试
Ubuntu 24.04 x86_64 编译与测试
macOS Intel、Apple Silicon 编译双架构通用包并发布，自动测试在 Intel 目标上运行

包含新图标的提交 ef2862077 已完成这一轮构建和发布，对应记录为 GitHub Actions 构建记录。

我选择保留一个持续更新的 Release，下载地址保持固定，安装包和提交信息随成功构建更新。构建或测试失败时不执行发布；如果分支已有更新提交，旧提交的发布任务会跳过，避免下载入口退回旧版本。

仓库中，main 保留上游基准，personal 保存我的改动和项目文档。单项功能从 personal 建立功能分支，验证后合入；同步上游时单独处理冲突和兼容性。具体平台和发布步骤见自动构建与发布说明。
