Deskflow 在 Ubuntu 上的锁屏控制与开机自动连接配置

发表于2026-10-18|更新于2026-10-20|软件

使用环境与故障现象

两台电脑共用一套键鼠，键盘和鼠标实际连接在 Windows 上。Windows 运行 Deskflow 服务端，Ubuntu 运行客户端，通过局域网接收键鼠操作。

本次配置环境：

项目 版本或状态
Linux Ubuntu 26.04.1 LTS
桌面 GNOME Shell 50.1、Wayland
Linux Deskflow Flatpak 版 1.27.0
Windows Deskflow 系统服务已运行，启动类型为自动
锁屏扩展 Allow Locked Remote Desktop 17

桌面正常使用时，键鼠可以跨电脑操作，但遇到了两个问题：

  • Ubuntu 锁屏后，无法通过 Deskflow 输入密码，必须在 Linux 本机解锁才能恢复控制。
  • Ubuntu 重启后停在首次登录界面，登录后自启动的 Deskflow 尚未运行。

这两种情况分别通过允许锁屏远程控制、自动登录后启动 Deskflow 处理。配置完成后的日常使用测试正常。

Deskflow 在当前 Wayland 环境中通过桌面的远程控制接口接收输入。GNOME 锁屏时会限制远程访问，导致键鼠控制中断。Deskflow 项目记录了相同现象，参见锁屏后无法控制客户端的问题记录。

安装允许锁屏远程控制的扩展

Allow Locked Remote Desktop 用于允许 GNOME 在锁屏期间继续接受远程连接。本次安装的是支持 GNOME 50 的 17 版。

扩展调整的是 GNOME 的远程访问限制，影响范围包括使用相关接口的其他远程控制程序。锁屏仍然保留，解锁仍需输入系统密码。实现可查看扩展源码。

测试锁屏控制

在 Linux 桌面中触发锁屏，再从 Windows 将鼠标移入 Linux 屏幕，唤出密码框并输入 Linux 登录密码。Linux 的锁屏快捷键为 Super+L，普通 Windows 键盘上的 Super 对应 Win 键；若 Windows 截获 Win+L，可以从 Linux 桌面菜单锁屏。

首次测试应保留本机解锁手段，例如必要时临时接入现有键盘。扩展启用后的功能以实际输入密码测试为准。

配置重启后的自动连接

首次登录界面由 GDM 管理，GDM 是显示登录页面、启动用户桌面的程序。登录后的锁屏仍运行在用户桌面中，因此 Deskflow 和扩展可以继续工作；重启后的 GDM 登录界面尚未加载这些用户程序。

配置结果与锁屏设置

配置检查已确认：

  • GNOME 扩展为 17 版，已启用且状态为 ACTIVE。
  • GDM 自动登录已开启，账户设置正确。
  • Linux Deskflow 登录自启动项已启用，使用现有客户端连接配置。
  • Windows Deskflow 服务正在运行，启动类型为自动。

配置后的日常使用测试正常。该配置用于登录后锁屏的远程解锁，以及自动进入桌面后启动 Deskflow。断电恢复还取决于电脑是否自动开机；磁盘解密、网络尚未建立等阶段不在这套桌面配置的控制范围内。
